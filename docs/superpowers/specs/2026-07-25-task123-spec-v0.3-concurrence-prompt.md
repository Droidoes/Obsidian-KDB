## The four rulings (R1–R4)

### R1 — Contract posture: per-entry salvage, retry, **no deterministic fallback** (§2.3, §3.4)

A parseable selector response is **never wholesale-discarded**. Python validates each entry against the closed world individually: foreign/malformed entries dropped, unknown expressions field-coerced, duplicates deduped (keep first), over-cap truncated in returned order — every deviation counted by class (`valid_entry_yield`, per-class attempted-violation rates → per-model leaderboard). Joseph's rule: *10 returned slugs — 1 duplicate, 3 malformed → the 6 good ones are kept.*

On selector failure (transport/timeout/unparseable): **retry once** (the #104/#106 budget), then **honest empty + typed `selector_failure` telemetry. There is no deterministic exact/alias fallback** — it resolves only string-identical keys, and `warren-buffett` string-resolves to nothing (#122 finding 4), so every fallback would silently revert to pre-#123 behavior for exactly the class #123 exists to fix. Consequences: opus5's A1 fallback is superseded; all three legacy T2Modes retire (`STRUCTURED` included); codex's F6 (fallback search space) is moot; the resolver survives only as evaluation instrumentation (exact_matchable annotations). Compensating controls: per-entry closed-world validation (the D9 output invariant — nothing foreign can leave the function by construction), selector-failure-rate hard gate, escaped-foreign-identity = 0 hard gate.

### R2 — Oversized spaces: one uniform pre-flight budget rule (§7.2)

Your F1 arithmetic was verified and adopted (thin ≈ 13–23 tokens/entity, largest domain 51/31%, vault thin ~127k–222k). But the resolution is not a per-surface model requirement. Joseph's rule: **before the stage-1 call, estimate the serialized thin input tokens; over 80% of the configured selector model's window → fail `budget_exceeded` without invoking the API** — zero spend, typed telemetry, never retried. Identical for every consumer — no whole-graph special case, no pass-1.5 special case. What fits is an empirical fact about the configured model (both surfaces pass against a 1M-window selector), reported honestly when it doesn't. Sharded thin = recorded contingency; lexical candidate generation stays rejected (your own v0.1 F4 premise).

### R4 — Staging posture: **always** two-stage (§2.1, §7.2)

Thin call → fat call, every source, every run. No single-stage path, no estimator-driven routing, no threshold to tune (SD-5 dissolved into the R2 guardrail). Rationale: Joseph's uniformity principle — the system never behaves conditionally when it can behave uniformly; the stage-1 recall gate is measured on 100% of traffic from day one. At today's scale results equal a single fat call's (largest domain 51 < M=150 ⇒ retention non-binding), for ~1k extra tokens per source. Stage-1 prompt is recall-oriented ("when in doubt, retain"); stage-2 evidence is presented in manifest order so fat stays unanchored to thin.
