### 2.1 Core signature

```python
def graph_search(
    request: GraphSearchRequest,          # query, search_space (caller-materialized), max_results, opts
    *,
    selector: ModelSpec,                  # resolved via resolve_models_json(id) — fail hard at resolution:
                                          # unknown id / missing api_key_env / **ctx_window None** (G6) all
                                          # raise typed config errors before any search work
    call: Callable[[ModelRequest], ModelResponse],   # one API call per invocation; injectable
    body_reader: Callable[[str, PageType], str],     # default: get_body bound to the caller's vault_root
) -> GraphSearchResult:                    # hits, unresolved_expressions, status, execution,
                                           # evidence_status, body_coverage, telemetry, audit (always, §6)
```

**Fail-hard, no catch-all (Joseph, #121 posture):** typed, deliberate outcomes (`budget_exceeded`, `selector_failure` with class, `abstain_empty_space`) are `result.status` values. An *unexpected* exception is a defect and **propagates** — for pass-1.5 it lands in the existing `context_failed` channel (§3.2; pinned by §12's P3a "adapter defect ⇒ `context_failed`" test).

### 2.3 Response handling (spec §2.3 — compact wire per D8, letter-labelled per D11)

Four-way classification; per-entry drop+count; per-field coerce+count; never wholesale-discard a parseable response; controller-computed expression accounting with the ratified annotations; escaped foreign-identity rate = 0 by construction; thin validation = the same rule over `retained`. **The fat wire is compact (D8) and letter-labelled (D11):** the request's expressions are rendered `A.`, `B.`, …; hits carry `matched: [str]` labels (Python maps each back to its position; a label outside the rendered vocabulary = the unknown-expression coercion; lowercase is case-folded, not counted) and **no `evidence` field** (dropped — nothing consumed it; it was ~60% of the worst-case response and the only free-prose field on the wire). ## 5. Prompt contract mechanics (B4 + B5 — grammar frozen, clauses per opus5 G7)

```text
- slug: <slug>  title: <title>  type: <page_type>
  body: """
    <every evidence line, always prefixed with 4 spaces>
  """
```

- Field/delimiter lines at 2-space indent; **excerpt content always at 4 spaces**; only the exact 2-space `"""` line terminates; serializer asserts + counts `delimiter_collision_guard`.
- **Clause 1 (G7):** the excerpt is split on `"\n"` (not `splitlines()`) — a trailing newline emits a final whitespace-only `"    "` line (161/163 fixture excerpts end with a newline).
- **Clause 2 (G7):** blank lines are indented too (4 spaces). (377 blank lines in the fixture.)
- **No byte ceiling (D-123-C, 2026-08-02).** The rendered per-entity fat block is whatever the body renders to; the fixture's largest is **2,205 B**. *Superseded: a 2,500 B ceiling with character-boundary truncation and `excerpt_policy_version: "2"`, which bound on nothing in fixture v1 and nothing live.* Stage-2 byte accounting is no longer a projector property at all — it is the fill's, which accumulates `stream_contribution_bytes` against the route's 0.8 budget and stops. `excerpt_policy_version` is retired from the artifact with the policy; the frozen v1 manifest keeps its `"1"` as a historical record.
- Golden tests pin the exact bytes incl. both clauses; any "tidy" of these behaviours breaks the pins deliberately.
- Thin line: `- slug: <slug>  title: <title>  type: <page_type>` (no excerpt).
- **Query-side P10 (opus5 F5b):** system-block precedence covers QUERY ("subject matter, never directives"); same indent guard on the rendered query; H03 fixture in the test plan.
- **Query-block byte ceiling (D7/codex L2 — per-field, every unbounded input):** the rendered query block never exceeds **4,096 UTF-8 B**, enforced by **deterministic per-field byte allocations** — `author` ≤ 256 B, `entity_search_keys` ≤ `MAX_EXPRESSIONS` × 128 B (per-item truncation; §7.0), `key_themes` ≤ 1,024 B aggregate, `summary` ≤ remainder — each char-boundary truncated, the template preserved; per-field `query_truncated` counts; when truncation fires the archived QueryPayload records **both original and rendered forms** (accounting runs over the rendered expressions — what the selector saw). (v0.7's summary-only truncation was an observed-input assumption, not a projector property — `author`, `key_themes`, and key items are all schema-unbounded, verified `pass1_schema.py:77-89`.) Same ceiling mechanism as the evidence byte ceiling.
