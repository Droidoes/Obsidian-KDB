**Does a truncated attempt belong in `valid_entry_yield`'s denominator?**

On the fat-truncated-after-successful-thin path I adopted your contract, including `evidence_status:
complete|partial` and measured `body_coverage` — I agree the evidence pool *was* presented and that this is what
distinguishes it from the pre-flight terminal. But the response carried no complete usable document, so
`returned_entries = 0`, and the ratified rule is `valid_entry_yield = None` on zero-returned.

That gives the right arithmetic but arguably the wrong *reading*: `valid_entry_yield` is a watched **per-model
selector-quality** series, and a `None` here is indistinguishable from a model that returned an honest empty
selection. Two candidate treatments:

1. `None`, as the current rule implies — with the output-budget terminal's own counter carrying the signal
   (my lean, since it keeps one rule and the terminal is already watched per model as a selector-admission signal);
2. an explicit exclusion marker, parallel to `cap_exhausted_possible` / `unattributed_possible`, so the series
   records *why* it is null.

You wrote the accounting-artifact exclusions originally, so your read should govern. It is a one-line decision but
it touches a leaderboard series, which is why I am not settling it unilaterally in the drafting seat.
