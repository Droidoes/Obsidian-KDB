# #123 P2.1a — Codex review: selector prompts + loader

Date: 2026-07-27  
Reviewer: Codex  
Verdict: **REVISE**

## Executive judgment

The loader and assembly mechanics are strong, and the measured arithmetic checks out. The prompt
bytes should not be frozen yet.

Three changes should land before P2.1f and D5 calibration:

1. Make the thin prompt explicitly cap-aware. Its current claim that false positives cost almost
   nothing becomes false when `N > M`, and “do not attempt to be selective” conflicts with the
   mandatory top-100 cut.
2. Give the fat prompt an explicit ordering criterion and require positive evidence rather than
   inference from an excerpt's omissions.
3. Fix multiline-title framing in `render_thin_line`; an H04 fixture alone cannot restore a
   boundary that the serializer permits graph content to forge.

These are bounded changes. The prompt corrections can replace existing paragraphs and should fit
the current headroom; the renderer correction is a deliberate P1 byte change, but this
pre-calibration window is the cheapest and safest time to make it.

## Findings

### F1 — HIGH — The thin instructions become internally contradictory at a binding cap

`kdb_search/prompts/selector_thin_v1.txt:20-30` says all of the following:

- retain every plausible identity;
- retaining an irrelevant identity “costs almost nothing”;
- do not attempt to be selective;
- rank and cut to the USER limit.

The first three are sound only while the cap is non-binding. At `N > M`, every weak retained
identity can displace a relevant identity, so a false positive no longer costs almost nothing.
The model is forced to be selective after being told not to be. The final two-line cut instruction
does not explain how to resolve that conflict or require the model to evaluate the entire list
before filling the cap. This invites early-list/position truncation precisely at the projected
~490-to-100 transition.

Recommended shape: make eligibility and cutting two explicit steps, with cap-aware economics.
For example:

> Evaluate every identity in EVIDENCE before deciding; never stop after filling the list and never
> use EVIDENCE order as a relevance signal. Treat an identity as eligible whenever its identity
> leaves a plausible semantic path to the QUERY. If the eligible set fits within the USER limit,
> retain all of it. If it exceeds the limit, rank the entire eligible set by likelihood that the
> entity's body would substantially help answer or explain the QUERY, then return the best up to
> the limit. At a binding limit, a weak candidate displaces another candidate, so choose the cut
> carefully. Dropping a relevant identity is unrecoverable; precision among retained identities
> remains the second pass's job.

This preserves the recall posture without pretending that precision has zero cost at the cliff.

### F2 — HIGH — H04 is a structural framing defect and should be fixed before calibration

`kdb_search/projection.py:53-55` interpolates `entity.title` into one f-string without indenting
continuation lines. Both stages reuse that identity line (`projection.py:58-64`). A title containing
`\nQUERY:` can therefore forge the same unindented boundary emitted by
`selector_thin_v1.txt:41-47` and `selector_fat_v1.txt:43-49`.

The premise in `kdb_search/tests/test_prompts.py:263-274`—that every evidence continuation line is
indented—is consequently false for multiline titles. “The title came from the graph” is not a
trust boundary: graph titles ultimately contain model-authored/source-derived content. Instruction
precedence prose helps only if the model can still identify which bytes are inside EVIDENCE.

Recommendation: fix `render_thin_line` so every title continuation line is indented as content,
using the same structural rule as `_scalar_lines`; this fixes both thin and fat identity lines.
Then add H04 as a regression fixture proving the forged header remains indented. A harder delimiter
in the template alone is insufficient because an unescaped title can forge that delimiter too.
Leaving the serializer unchanged and relying only on H-class fixtures tests the defect without
removing it.

### F3 — MEDIUM — Fat ranking and excerpt honesty need one explicit positive-evidence rule

`kdb_search/prompts/selector_fat_v1.txt:19-25` says “best first” but supplies no ordering criterion.
It distinguishes substantial coverage from a passing mention, which is useful, but does not tell
the selector how to order two legitimate hits. The same paragraph says absence from an opening
excerpt is weak negative evidence without saying that omitted text is not positive evidence. That
can license speculative selection, especially for title-only entries.

Recommended replacement/addition:

> Rank by directness and strength of positive support: entities centrally about the QUERY first,
> then entities providing substantial supporting coverage. Use breadth across QUERY fields or keys
> as a tiebreaker, and never use EVIDENCE order as a relevance signal. An opening excerpt may omit
> relevant material, but missing text is not positive evidence: do not select an entity merely
> because its unseen body might contain the topic. Judge title-only entries only from positive
> signals in their identity line.

The review prompt calls precision@5 the project's “only normative gate.” The repository is narrower:
its formula is normative (`docs/superpowers/specs/2026-07-25-task123-semantic-graph-search-spec.md:
385-395`), but it is a watched metric, not a numerical admission gate; the D7 gate table is at
`:413-422`. This wording correction does not weaken the ranking recommendation—top-order quality is
still the comparison the metric measures.

### F4 — LOW — The unversioned-filename typed failure is not pinned on the real import path

`kdb_search/prompts.py:70-71` calls `.group(1)` on `_VERSION_RE.search(...)` at module import before
the checked path at `:127-133`. If a real `_FILENAMES` entry loses its version suffix, import raises
`AttributeError`, not `PromptTemplateError`. The test at
`kdb_search/tests/test_prompts.py:164-167` monkeypatches `_FILENAMES` only after the module has
successfully imported, so it does not exercise that failure mode.

Recommendation: derive the exported constants through one checked version parser after
`PromptTemplateError` is defined, and reuse it in `load_template`.

### F5 — LOW — The wheel-test substitution leaves a small, real packaging gap

`kdb_search/tests/test_prompts.py:509-547` verifies the setuptools declaration covers the files and
that source-checkout resolution is independent of CWD. It does not prove that a built wheel actually
contains the templates or that import/resource lookup works after installation. Parsing
`pyproject.toml` is not an execution of the build backend.

This does not block prompt freezing or calibration: `pyproject.toml:46-50` is correctly declared and
module-relative loading is correct. Add a build-wheel/install/import smoke in release CI or when
offline build tooling is available.

## Answers to the seven review questions

1. **Thin recall at `N > M`: unsafe as written.** The two-clause shape contains conflicting
   economics and no full-list-before-cut rule. Absorb F1 before freezing.
2. **Fat ranking: underspecified.** Add directness/support/breadth criteria and prohibit evidence
   order as a ranking signal. See F3.
3. **Does `max_results` invite padding? No change needed.** “At most,” explicit honest empty, and
   “padding ... is a defect” are collectively clear. Rendering the actual cap is the right
   measurement contract.
4. **Excerpt-honesty clause: directionally true but incomplete.** Add “missing text is not positive
   evidence”; otherwise it can justify speculative over-selection.
5. **Is 691 B enough? Yes for these corrections.** Replace the current selection/ranking
   paragraphs rather than stacking more prose. Re-measure exact rendered bytes after absorption;
   no blueprint bump appears necessary.
6. **Are unindented headers enough? Only after fixing the serializer.** Choose the
   `render_thin_line` continuation-indent fix plus H04 regression coverage. A novel delimiter
   without escaping is still forgeable; fixture-only acceptance leaves the boundary unsound.
7. **Mechanics:** single-pass substitution is a valid P10 control; unknown-slot, unused-value, and
   duplicate-slot guards are correctly enforced (`kdb_search/prompts.py:177-204`); text-mode digest
   normalization and literal `repo_path` are sound (`:135-173`); the module-over-namespace
   precedence works and is tested; the schema examples really are passed through the production
   validators (`kdb_search/tests/test_prompts.py:353-402`). The public digest rename is complete
   within `kdb_search`. F4 and F5 are the two mechanics gaps found.
