## 1. The one genuine reviewer conflict: C4 classes 4/5 (duplicate slug, over-cap)

| | codex (v0.1 F6 → v0.2 gate 6) | opus5 (v0.2 §1) |
|---|---|---|
| Position | duplicate + over-cap = contract violations → whole-response invalid → fallback (he marked gate 6 RESOLVED under this) | duplicate + over-cap = **benign over-supply → coerce** (dedupe keep-first / truncate in returned order, typed telemetry); fail-closed reserved for identity breaches + the unrecoverable/ambiguous |

**Assessment (Kimi):** opus5 is right, on three independent grounds:

1. **Ratified project principle.** #104's coerce-don't-reject already truncates LLM over-supply (`>10 entity_search_keys` → 10) rather than rejecting; D-119's governing rule is "reject ambiguity, not harmless representational differences." A duplicate slug is not ambiguous (keep first); an over-long list is not ambiguous (truncate in returned order — that order *is* the selector's own ranking, a deterministic authority). A foreign slug IS an identity breach and still rejects. Joseph's own #119 framing ("why should a missing dash fail the LLM output at all?") is this principle.
2. **Internal consistency.** v0.2 already truncates stage-1 over-cap as a "pragmatic exception" whose justification — no identity can escape, retained set re-validated — applies *identically* to stage-2 truncation. Same deviation class, opposite treatment, harsher on the path carrying the actual result. The split removes the exception by unifying the rule.
3. **Operational consequence.** The §3.4 fallback is exact/alias resolution — and `warren-buffett` exact-resolves to *nothing* (#122 finding 4). Every fallback on a person-key source is a silent reversion to pre-#123 behavior for exactly the case #123 exists to fix. Under strict-C4, one duplicate in an otherwise perfect 10-hit response loses all ten → empty T2. Strictness would convert selector noise into status-quo reversion.

codex's underlying concern — measurability of selector compliance — survives intact: the **attempted**-violation rate (his own F7 split) still records classes 4/5 from raw output; coercion does not hide them. And opus5's compensating control gives the strictness concern teeth at the metric layer: **fallback rate becomes a hard gate** (his minor 1), because the fallback rate *is* the "is #123 delivering" measure.

**Proposed §2.3 (v0.3):**

| class | kind | disposition |
|---|---|---|
| 1. invalid JSON shape | unrecoverable | fail-closed → fallback |
| 2. foreign slug | identity breach | fail-closed → fallback |
| 3. unknown `matched_expression` | ambiguous attribution | fail-closed → fallback |
| 4. duplicate slug | benign over-supply | **coerce**: dedupe keep-first, typed telemetry |
| 5. over-cap | benign over-supply | **coerce**: truncate to `max_results` in returned order, typed telemetry |
| 6. malformed expression accounting | ambiguous | fail-closed → fallback |

Coerced responses are honest partials, not failures. Stage-1 and stage-2 come under one rule. **Joseph rules** (recommendation: adopt, with codex's dissent recorded in §11).

## 2. codex F1 — thin arithmetic corrected; whole-graph stage-1 needs a recorded strategy

v0.2's thin figures (~5 tokens/entity; 48k at vault) were wrong — measured ~13–23/entity ⇒ whole-graph thin at vault ≈ **127k–222k tokens**. Crucially, the bust is **only** the whole-graph human/CLI/MCP surface: pass-1.5's largest domain space (~3,000 at vault) thin-projects to **~40k–70k — fits the 100k budget comfortably**.

codex's three options for whole-graph stage-1:

1. **Per-model stage-1 budget/window requirement.** Whole-graph thin ≈ 130–220k fits current long-context flash models (gemini-3.6-flash: 1M window). The SD-5 threshold is already per-model; this adds a recorded selector-model requirement: window ≥ ~256k at vault scale for the whole-graph surface. Human queries are interactive/low-volume — a 130–220k-token call is cents, not the bulk workload (pass-1.5 is). **Kimi recommendation.**
2. **Sharded/hierarchical thin + global merge.** Reintroduces the merge/ordering/replay complexity the SD-4 table rejected for option 3. Documented fallback if the pool ever lacks a long-window selector.
3. **Lexical/structural candidate generation for oversized spaces.** Reintroduces the unmeasured-recall cap codex himself rejected as load-bearing (his v0.1 F4).

**Joseph rules** (recommendation: option 1, with option 2 recorded as the contingency design).
