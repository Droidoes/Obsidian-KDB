## 0. Post-ratification amendments (Joseph, 2026-07-26 — binding; panel-informed, dissents recorded)

- **D10 — invariant-first prompt ordering: EVIDENCE before QUERY, both stages (Joseph, 2026-07-27 — BINDING; amends §2.1).** The USER message ordered `QUERY` (≈4 kB) before `EVIDENCE` (≈250 kB at M=100). That places the **only per-source-variable block ahead of the block that is invariant across every source compiled into the same space**: the evidence is *"every SearchSpace entity, in the space's deterministic order"*, identical for all sources sharing a domain at a given graph state. Two independent costs, and the fix is the same for both: (i) **prefix reuse** — a cache prefix breaks at the first varying byte, so the small variable block in front forfeits reuse of the large invariant one, which matters most for the queued vault ingestion (1,586 notes, many per domain); (ii) **attention position**, which holds regardless of any provider's caching behaviour — the query currently sits ~250 kB from the generation point, and placing it last puts it adjacent. **Raised by Joseph** from the principle that the fixed instruction and the per-call payload should be cleanly separated, with the per-call part carried as input; the reorder is that principle applied inside the USER message. **Scope:** ordering only — byte totals, §7.0a maxima, allowances, and the M=100 static guarantee are all unchanged, and the D10 label is unrelated to vision v1.2's D1–D10 numbering. **Ratified as an official fix, explicitly NOT as an experiment arm** (Joseph: *"reordering should not be part of the experiment, it should be the official fix… after that done, we can experiment"*) — a defect is corrected, not A/B'd, and the #125 stage-2 representation experiment runs on top of the corrected order. **Cost to adopt: zero code.** `kdb_search/prompts/` is empty and prompt assembly is unwritten P2 work, so this lands as a spec/blueprint amendment that P2 then implements correctly the first time. Had it been found after P2, it would have cost a rewrite plus a re-run of anything already measured.
- **D11 — letter key-labels replace zero-based indices on the wire (Joseph, decided 2026-07-26, landed 2026-07-27 — BINDING; amends D8(i)/(iii)/(iv) and D9.2's measured consequence; blueprint §2.3/§7.0/§7.0a/§12).** **Sequencing note, so §0 does not read as a chronology:** this call predates D10 but lands after it, because the amendment was deliberately held until #125's Q1 was settled — there was no point re-deriving a byte table if the answer restructured the passes. Joseph closed Q1 on 2026-07-27. **The decision.** `entity_search_keys` render as `A. warren-buffett`, `B. owner-earnings`, …, and `matched`/`unresolved` carry **letters** (`matched: [str]`). **Why, precisely:** a letter is **not an ordinal**, so the 0-vs-1 base ambiguity ceases to exist. That ambiguity was the worst class of defect available here — a *protocol* disagreement producing a *systematic* error, where a one-based response against a zero-based wire mis-attributes **every** hit by one and each mis-attribution looks like a correct answer. What remains after D11 is the model being wrong about relevance, which is a quality question §8.3 already measures. **Second, it unifies the wire under one rule:** slugs already had to appear verbatim as printed, while indices had to be *computed* from position — two mental models, and the computed one is where the silent failure lived. Every identifier on the wire is now a verbatim echo of something in the prompt, which collapses the response instruction to a single line. **Coercion (§2.3):** a lowercase label is **case-folded** (`"a"` → `A`) — one deterministic reading, so the project's coerce-don't-reject rule applies; a label outside the rendered vocabulary is coerce-dropped and counted, exactly as an out-of-range index was; and an **integer is simply not a label**, so the old base disagreement now fails *loudly* (counted in `unknown_expression`) instead of silently. **Mechanics:** `WIRE_INDEX_BASE` is replaced by `WIRE_LABEL_ALPHABET` + `expression_labels(n)`, the single derivation source for the rendered marker, the accepted response vocabulary and §7.0a's schema-maximum documents; the alphabet stops at `Z` rather than extending to `AA` because the byte bound binds at 14 labels, long before the alphabet does. D8's explicit `isinstance(bool)` guard is **dropped** — it existed because `bool` is an `int` subclass, and a `bool` is not a `str`. **Arithmetic (§7.0a, derived by test, not asserted here):** a quoted `"A"` costs 3 B against `0`'s 1 B across 51 label lists (50 `selections` + `unresolved`) ⇒ **+1,020 B**, so the FAT exact max is **9,271 B** (was 8,251) and the break-even **14 expressions** (was 22). **What does NOT move, stated explicitly because a moving wire figure invites the wrong inference:** the rendered marker `"A. "` is byte-identical to `"0. "`, so the 4,096 B query ceiling, the per-field allocations, the ≤ ~257 kB worst-case request, `max_tokens` at thin 29,000 / fat 26,000 and the **283k < 320k static guarantee all stand exactly as ratified**; thin's exact max is **unchanged at 12,314 B** (its wire carries no expression addresses); and `VISIBLE_OUTPUT_ALLOWANCE_FAT` **stays 10,000** — 9,271 ≤ 10,000 is a *proof* under `tokens_lte_bytes`, not a working buffer wanting slack, and raising it would spend the guarantee's ~37 kB spare to buy nothing. **The one real cost, recorded rather than buried:** headroom falls 1,749 B → 729 B and `MAX_EXPRESSIONS = 10` now sits **4 under the cliff instead of 12**. This **strengthens D9.2** rather than threatening it — a P5b CLI/MCP caller needs only 14 expressions to re-open the truncation chain, so a consumer-neutral core bound is more load-bearing than when the cliff sat at 22.

### 2.2 What the selector is asked to do

Rank the entities **relevant to the query**, best first, up to `max_results`; attribute each hit to the expression(s) it answers — **by letter key-label** (the request's expressions are rendered `A.`, `B.`, …; the selector returns those letters, Python maps each back to its position — D8 as amended by **D11**); leave `unresolved_expressions` explicit when nothing in the space is relevant. ### 2.3 Selector output schema + per-entry validation & salvage (R1 — Joseph, 2026-07-25)

```json
{
  "selections": [
    { "slug": "…", "matched": ["A", "C"] }
  ],
  "unresolved": ["B"]
}
```

(`matched` holds **letter key-labels drawn from the request's labelled expressions** — `A`, `B`, … as printed in the query block — no repeated expression strings on the wire, no per-hit `evidence` field — D8 as amended by **D11**. **Every numeric maximum is stated (D8 mechanics, codex N2):** `selections` ≤ `max_results` (≤ 50 globally); `slug` ≤ `MAX_SLUG_LEN` (120 B — `common.paths`); `matched` ≤ `MAX_EXPRESSIONS` unique labels, each a member of the rendered vocabulary (`expression_labels(len(expressions))`); `unresolved` ≤ `MAX_EXPRESSIONS` labels — the advisory list labelled, keeping it bounded. **Every maximum derives from `MAX_EXPRESSIONS` (D9), not from pass-1's schema**; the exact serialized maxima and the compact-JSON grammar that produces them are recorded in blueprint §7's constants table, with the synthetic schema-maximum tests as executable authority.)

**Governing principle (Joseph's first-principle ruling): take the content, not the semantics — a parseable response is never discarded.** Python validates each entry independently against the closed world, drops only what is invalid, coerces what has a unique deterministic reading, and counts every deviation by class. Joseph's example is the rule: 10 returned slugs — 1 duplicate, 3 malformed → **the 6 good slugs are kept**. This supersedes v0.2's whole-response fail-closed (codex's F6 position; his dissent and the compensating controls are recorded in §11).

**Response-level classification (codex concurrence #1 — four-way, exactly one applies):**
1. `unparseable_response` — no complete JSON document → §3.4 retry.
2. `structurally_unusable_response` — valid JSON but not an object carrying a `selections` array (`{}`, `{"selections": "invalid"}`): there is nothing to salvage, yet it is not a parse failure → §3.4 retry.
3. `all_entries_dropped` — a parseable, well-shaped response whose `selections` array is non-empty but **every** entry is dropped by per-entry validation (e.g. systematically hallucinated foreign slugs): the selector malfunctioned, not the query → §3.4 retry (model-correctable attempt) + a watched `all_entries_dropped` rate.
4. **`selections: []` is none of the above** — a valid, empty selection is the **honest-empty completed response** (correct abstention, class E semantics), never a failure; `valid_entry_yield` is defined as `valid/returned` and is `None` when `returned = 0` (empty-response quality is metric 6's job, §8.3, not the yield's).

Separately, **before any call**, the §7.2 R2 pre-flight budget check can fail the request as `budget_exceeded` — deterministic, zero-spend, never retried. Classes 1–3 after retry exhaustion land as `status: selector_failure` with the class recorded (feeding the §8.4 selector-failure series — **diagnostic**, ceiling 100%, since the 2026-07-26 adjudication).

**Per-entry drop + count** (entry identity invalid):
- **foreign slug** (∉ search space) — identity breach; the entry is dropped, never repaired by similarity;
- **malformed entry** (missing/wrong-typed `slug`, unserializable fields).

**Per-field coerce + count** (unique deterministic authority exists):
- **`matched` label outside the rendered vocabulary** (∉ the request's labelled expressions — D8's wire form of the unknown-expression class, D11's letter form of it) — removed from that entry's list (the hit's identity is valid; the stray attribution is noise); a hit left with zero matched expressions stands as an unattributed hit. **A lowercase label is case-folded, not counted** (D11): `"a"` has exactly one deterministic reading, and the project's rule is to normalize a benign deviation rather than reject it. **An integer is no longer a label at all** — the type check drops it and counts it, which is the point: under D8's integer wire a base disagreement mis-attributed *silently*, with every hit looking correct;
- **duplicate slug** — keep first occurrence (the selector's own returned order is the authority), drop later ones; **duplicate `matched` label within an entry** — dedupe (D8 mechanics);
- **over-cap** (`len(selections) > max_results`) — truncate to `max_results` in returned order.

**Controller-computed expression accounting:** after validation, every request expression is *matched* (≥1 validated hit attributes it) or *unresolved*. **The controller computes this alone (D-123-F, 2026-08-02).** *(Superseded: the selector's advisory `unresolved` list was an input to that computation and discrepancies were counted as `selector_accounting_delta`, never a failure class. The field is off the wire; the delta is deleted. It answered a different question — which keys nothing in EVIDENCE answers — so the two diverged whenever EVIDENCE supported a key the result cap then excluded, and a perfectly-behaved selector scored as disagreeing. Nothing read the series.)* **What `unresolved_expressions` means, stated because it is easy to over-read:** keys that no RETURNED hit attributes. It is a claim about the answer, never about the graph — thin's retention ceiling and the stage-2 fill both cut the space the selector ever saw. **Recorded consequence of D8's bounded addressing (opus5 O3), unchanged by D11:** an *invented* expression is now unrepresentable — under the old string form a selector could return an unresolved value absent from the request, which the delta surfaced as a conformance signal; addressed by index or by label alike, an out-of-vocabulary value is coerce-dropped and the delta narrows to a count mismatch. The trade is accepted (a bounded wire is worth more, and out-of-range indices are themselves the signal), but the series' meaning is narrower than pre-D8 and should be read that way. Two artifact annotations keep artifacts out of the abstention metric (§8.3 metric 6): cap-induced unresolveds are annotated `cap_exhausted_possible` when `len(hits) == max_results` (opus5 minor 2); and hits left with zero matched expressions after unknown-expression coercion are counted (`unattributed_hit_count`), with expressions whose only validated hits are unattributed annotated `unattributed_possible` and likewise excluded from abstention scoring (opus5 §2.4 — a genuinely relevant entity can be present in `hits` while its expression reports unresolved; that is an attribution artifact, not an abstention judgment).

**Stage-1 (thin) validation:** the identical per-entry rule — foreign/malformed dropped, duplicates deduped, over-M truncated — applied to the retained-slug list. One rule, both stages.

**Telemetry:** every dropped/coerced entry is counted by class (`attempted_violations{foreign_slug, malformed_entry, unknown_expression, duplicate_slug, over_cap}`) plus `valid_entry_yield = valid / returned` — first-class selector-quality measures per model (§6.3, §8.3). The **escaped** foreign-identity rate remains **0 by construction** (post-validation output is membership-checked) and stays a hard gate (§8.4).

### 3.3 Missing/empty space

Empty space (domain-empty or `domain_missing`) → `status: abstain_empty_space`, `execution: not_executed`, no selector call (zero spend), T2 empty, abstention recorded as correct-by-design with the reason typed (`domain_empty` | `domain_missing`); T3 expands from T1 seeds only (existing behavior when T2 is empty — including the cold-start 2-hop widening rule, which stays).

### 3.4 Retry, then honest empty — **no deterministic substitution (R1 — Joseph, 2026-07-25)**

On **selector failure** — transport error, timeout, or any §2.3 response-level class (`unparseable_response`, `structurally_unusable_response`, `all_entries_dropped`; model-correctable/transient classes per D-119's "retries only for model-correctable failure classes"): **retry the LLM call**, bounded budget (2 attempts total, the #104/#106 precedent). `budget_exceeded` (§7.2 R2) is **not** a retry class — it is deterministic, fails before any API call, and is reported, not retried. **`budget_estimation_miss` (D7, re-typed per opus5 M1) is likewise never retried:** the provider's context-length rejection means the estimate under-called a rendered request; the same request fails identically. It is the same event as `budget_exceeded`, detected one step later — so it is typed **`status: budget_exceeded`, `detected: post_call`, `budget_side: input`** (the preflight's is `detected: pre_call`). **Its output-side sibling (D9)** — a length-finish-reason truncation, i.e. hidden reasoning plus visible JSON exceeding the reserved provider-total output — is typed identically with **`budget_side: output`**, is likewise never retried, and is likewise excluded from the §8.4 gate, the call is recorded as attempted (spend possible), and its rate is watched per model. It is **excluded from the §8.4 selector-failure-rate gate** — an estimator under-call is *our* mechanics, not the model's behavior, and typing it `selector_failure` would contaminate the one series that answers whether #123 works and penalize smaller-window models systematically (the exclusion is about what the series *measures*, so it holds whether or not the series gates anything — see §8.4) (the `budget_exceeded`-is-not-`selector_failure` precedent; the `cap_exhausted_possible`/`unattributed_possible` exclusion principle).

After the retry budget is exhausted: **honest empty T2 + `selector_failure` telemetry with the failure class** — and nothing else. **There is no deterministic exact/alias fallback.** Rationale (Joseph's ruling): the deterministic resolver cannot be the catch-all — it resolves only string-identical keys, and `warren-buffett` string-resolves to *nothing* (#122 finding 4); if the deterministic routine were that good, the LLM search would not be needed. This **supersedes opus5's A1 degraded-mode fallback** (vision P1 v1.2–v1.3) and moots codex's F6 (fallback search-space question — there is no fallback).

**Record correction (opus5 concurrence §1.1 — the trade stated honestly):** describing the fallback as "a silent reversion to pre-#123 behavior" was imprecise — pre-#123 behavior is what `STRUCTURED` delivers (0–2 T2 hits/source on the 2026-07-25 cold runs), so a failed source *without* a fallback lands **strictly below** status quo (zero hits), not at it. R1 deliberately accepts that strictly-worse failure mode, for two reasons that are the actual justification: (a) a silent partial-quality path that *resembles* success corrupts the one signal that tells us whether #123 works — honest empty plus a selector-failure-rate hard gate is the measurable choice; (b) keeping the fallback keeps `STRUCTURED` alive as a second production T2 architecture indefinitely. Both outweigh recovering 0–2 hits on a gated-rare path.

**Reversibility channel (supersedes opus5 concurrence §2.1 — Joseph, 2026-07-25):** there is no `foregone_deterministic_hits` telemetry. Joseph's ruling: the deterministic method is not a valid search method, so what it "would have recovered" is not a meaningful measure and its output is never surfaced, even as telemetry. R1's reversibility runs through **selector-quality evidence** instead — `valid_entry_yield`, per-class attempted-violation rates, retry and failure rates per model (§6.3) → selector model choice and prompt iteration.

Consequences:
- **T2Mode disposition (updated):** all three legacy modes — `LEGACY`, `LAYERED`, **and `STRUCTURED`** — retire with #123's ship; the selector is the only production T2 path. Migration mechanics (call-site removal, test disposition) are blueprint scope.
- The deterministic resolver has **no role anywhere in the system** (Joseph, 2026-07-25) — not as fallback, not as per-hit annotation, not as a comparator metric, not as would-have-recovered telemetry. String matching is not a valid search method; its output is never surfaced.
- **Selector-failure rate** (retry-exhausted) is the "is #123 delivering" measure (§8.4 — opus5's compensating control, repurposed: there is no fallback rate left to gate). **Diagnostic since the 2026-07-26 adjudication** — its ceiling is 100%, so it reports rather than rejects; the measure's *meaning* is unchanged, only its power to block.

## 6. Evidence status, telemetry, and the two denominators

### 6.1 Evidence status (codex F5)

- `complete`: every entity **in the fat-selector evidence pool** produced excerpt text.
- `partial`: ≥1 pooled entity title-only. `body_coverage < 1.0`.
- `not_applicable`: no fat stage executed (abstention, failure).
- Per-caller acceptance policy: pass-1.5 accepts partial (title-only entities simply compete with weaker evidence); the evaluation program (§8) fails closed if coverage drops below its ratified threshold. A title-only fallback is never reported as a normal complete observation.

### 6.2 The two denominators (codex clarification 5 — pinned as KPIs)

- **Selector-eligible relevance quality**: rates computed over requests with a non-empty space. Domain-empty/domain-missing abstentions are **not** selector failures.
- **All-request search availability**: the domain-empty rate stays visible end-to-end (accepted cold-start reality, P3-b). Neither denominator substitutes for the other.

### 6.3 SearchTelemetry (controller-produced)

Counts — eligible-space size, stage-1 retained, stage-2 hydrated, stage-2 title-only, returned entries, **valid_entry_yield** (`None` when returned = 0, §2.3), **per-class attempted violations** (§2.3), `all_entries_dropped` occurrences, `unattributed_hit_count`, `query_truncated` occurrences (D6), `search_artifact_write_failures` (warn-only envelope sink — codex minor), retry attempts, `selector_failure` class — `status`, `execution`, per-stage model route + stamps, per-stage latency + cost, **pre-flight budget record per stage (`budget_estimate_tokens`, `selector_window`, `headroom_factor`, routing outcome, `detected: pre_call|post_call`, `budget_side: input|output`, `visible_output_allowance`, `hidden_output_reserve`, provider `finish_reason` when post-call — §7.2 R2 as amended by D6/D9)**, **thin/fat concordance (fat top-10 ∩ thin top-20 — §8.3)**, **`thin_bytes_per_token` / `fat_bytes_per_token` — the MEASURED density of the request each stage actually sent (rendered bytes ÷ the provider's own reported prompt-token count; `None` where the stage never ran or no response arrived, never 0). ### 8.3 Metrics (separated per codex F7 — no conflated boundaries)

1. **Scope coverage/recall** over the complete caller-materialized space (is any relevant entity in the space at all — not an @K metric);
2. **Stage-1 candidate recall** — the predeclared SD-4 gate, in its measurable form (opus5 §2.3): production **M=100 (D7)** is non-binding on every domain subtree in the fixture (largest 51 < 100 ⇒ retain-all by controller enforcement — §2.1) but **binding on the 163-entity whole-graph space** — recall@100 there is a real measurement, not 1.0 by construction. The gate measures stage-1 recall at **reduced M where the fixture makes it binding** — M=10 and M=20 over the 51-entity value-investing domain, M=20 and M=40 over the 163-entity whole graph — with the threshold predeclared on that curve. The property under test: does thin-title LLM selection retain relevant identities **when it must discard** — the honest test of the vision-Q3 thin-text skepticism the two-stage design rests on, measurable at any binding ratio. **M=100 is the production constant (D7)** — sized so the fat request's absolute worst case fits the configured pool's smallest budget by construction (§7.2); **the curve also gains M≈5 over the 163-entity space (~3% retention)** so the gate brackets production's vault-scale regime (100 / ~3,000 ≈ 3.3%) before authorizing vault ingestion (opus5 M2 — the earlier points, 12–40%, never reached the regime the gate approves);
3. **Final selector precision@5, recall@5, MRR** (ordering). **precision@5 is NORMATIVE, not a harness decision** — settled 2026-07-26, before any experiment runs, because the label set makes the choice enormous: **216 acceptable labels against 89 relevant** (2.4×), so whether *acceptable* counts as precision-positive moves the headline number more than most selector differences would. Leaving it to the harness means the first implementer decides it silently and every later comparison inherits that decision unexamined.

   ```text
   precision@5 = (relevant_returned + acceptable_returned) / returned_in_top_5
   ```

   - **Numerator** — a returned slug labeled `relevant` **or** `acceptable_alternatives` counts as precision-positive. This follows directly from the ratified two-tier label policy, whose `acceptable_alternative` tier is defined *"defensible and precision-neutral but not required for recall"*: a tier explicitly defined as precision-neutral cannot also be scored as a precision error. Only `neither` — irrelevant, generic, unsupported, or provenance-only — is a precision error.
   - **Denominator** — `min(5, returned)`, i.e. the results actually returned inside the top-5 window, **never a fixed 5**. Padding a short list to 5 would score absent results as errors and penalize honest brevity, which is the opposite of what R1's honest-empty invariant protects.
   - **`returned == 0` ⇒ `None`**, excluded from the aggregate rather than scored 0. Identical in kind to `valid_entry_yield`'s zero-returned rule (D9.6): an empty selection has no returned population, so it cannot supply a denominator, and scoring it 0 would make a correct abstention indistinguishable from a wrong answer.
   - **Aggregation is micro**, consistent with the artifact's `class_a_recall_aggregation: micro_relevant_slug` — one probe with many results must not outweigh five probes with few, and mixing macro precision with micro recall would make the two series incomparable.
   - **Probes with no required set do not enter the recall series** (they cannot fail a recall they do not assert) but **do** enter precision. The artifact marks them explicitly — `scoring_role: "precision_only"` per probe, listed in `gates.metric_rules.class_a_precision_only_probes` (**A09, A12**). They are **not** abstention probes and must not join that denominator: unlike A10, which has zero acceptable alternatives and is a true domain-gated abstention, A09 and A12 carry non-empty `acceptable_alternatives`, so returning one of those slugs is *correct* and scoring it as a failed abstention would invert the label. Three distinct roles, not two: required-set probes score recall **and** precision; precision-only probes score precision alone; abstention probes score neither and instead answer whether the selector correctly returned nothing.
4. **Attempted contract-violation rate** from raw selector output, per §2.3 class, plus **valid_entry_yield** — the selector-quality series (Joseph's leaderboard counter);
5. **Escaped foreign-identity rate** — hard gate **0** (zero by construction post-validation; the obligation is the proof, the attempted rate is the signal — opus5);
6. **Semantic abstention accuracy** over non-empty eligible spaces (class E) — computed over controller-computed accounting, with `cap_exhausted_possible` and `unattributed_possible` annotations excluded (§2.3);
7. **Domain-empty/domain-missing policy outcomes** — reported as **availability**, never selector relevance quality (§6.2).

Plus: **selector-failure rate** (retry-exhausted) + retry rate; **thin/fat concordance** (Joseph's [1]: the fraction of fat's top-10 falling inside thin's ranked top-20, per source — the "does fat earn its cost" watched series; HIGH values are evidence for a later thin-only simplification, LOW values are evidence bodies are load-bearing — decision deferred to a later task, arbiter = the truth-set thin-only vs thin→fat A/B, §10; note high concordance can coexist with both stages missing a hard probe, so concordance never substitutes for truth-set recall. **Scale caveat — opus5 §2.5:** at vault scale thin ≈ 40k–70k tokens vs fat ≈ 14.5k per source, i.e. thin becomes the cost driver (3–5×), so the question the metric answers *inverts* to "does thin earn its cost" — and the natural vault-scale simplification is then **sharded fat** (option 3), not thin-only.
